# ADR-0001: 技术选型

## 状态

Accepted

## 上下文

从零构建一个 A 股因子研究脚手架，需要选择核心技术栈。约束条件：

- 研究基础设施，不是策略框架
- 依赖精简，不引入重型框架
- 数据源可插拔，默认 Tushare Pro
- 存储与计算主力是 DuckDB

## 决策

| 维度 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.11+ | 量化研究生态最成熟，3.11 有性能提升 |
| 依赖管理 | uv | 比 poetry 快 10-100x，锁定文件跨平台一致 |
| 存储 | DuckDB | 嵌入式 OLAP，零运维，Parquet 生态好，SQL 接口对研究者友好 |
| 计算 | Pandas | 生态最成熟，社区资源最多，与 DuckDB 集成好 |
| 数据源 | Tushare Pro（可插拔） | A 股数据覆盖最全，API 稳定，有免费额度 |
| 测试 | pytest | Python 事实标准 |
| CI | GitHub Actions | 与 GitHub 集成最简单 |

## 否决的备选

| 备选 | 否决理由 |
|---|---|
| Polars | 性能更好，但生态成熟度不如 Pandas，社区资源少。个人项目优先生态 |
| PostgreSQL | 需要运维，嵌入式 DuckDB 对研究场景更友好 |
| AkShare | 数据源不稳定，接口变动频繁。作为备选数据源保留 |
| Poetry | 性能不如 uv，锁定文件格式不统一 |
| Conda | 过重，uv 已经覆盖包管理 + 虚拟环境 |

## 后果

- Pandas 的 API 在部分场景下不如 Polars 直观，但社区资源弥补了这个差距
- DuckDB 的并发写能力有限，但研究场景通常是单写多读，可以接受
- Tushare 的免费额度有限，但数据源层设计成可插拔，后续可以加 AkShare / 聚宽等
